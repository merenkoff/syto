# Фаза 1 — Голосовой спайк

Статус: 🔄 · Начата: 2026-09-24 · Завершена: —

## Цель

Доказать или опровергнуть главную идею проекта: обычное приложение без root на
телефоне пользователя может **само снять трубку, сказать абоненту фразу, услышать
и понять ответ, провести короткий диалог и положить трубку**, целиком на устройстве.
Не продукт, а серия экспериментов с записанными результатами.

## Гейт G1

На выходе — запись в `DECISIONS.md` с одним из трёх решений:

- **Go.** Все критерии ниже выполнены. Фаза 5 остаётся в плане, порядок 2 → 5 → 4 → 3 → 6.
- **Pivot.** Работает частично (например, только на части устройств или только «говорить, но не слышать»).
  Записываем, что именно работает, и выбираем один из вариантов пивота из 1.6.
- **No-Go.** Абонент не слышит бота или бот не слышит абонента на тестовом устройстве,
  и обходные пути из 1.3 не помогли. Фаза 5 отменяется.

Критерии Go (по чек-листам подфаз):

| Критерий | Порог |
|---|---|
| Автоответ на входящий с незнакомого номера | ≥ 19 из 20 тестовых звонков |
| Абонент разборчиво слышит приветствие | ≥ 9 из 10 тестовых звонков |
| Бот правильно распознаёт ключевое слово из чистой фразы абонента | ≥ 7 из 10 фраз на основном языке |
| Полный диалог (приветствие → ответ → реакция → отбой) на реальных звонках | ≥ 3 реальных звонка за полевой тест, расшифровка осмысленна |
| Задержка от конца фразы абонента до начала ответа бота | ≤ 3 с в типичном случае |

## Зависимости

Фаза 0 (APK на телефон). Ответы на открытые вопросы 1–3 из `STATUS.md`
(устройство, второй телефон, языки).

## Гипотезы, которые проверяем, в порядке дешевизны и опасности

| # | Гипотеза | Риск | Подфаза |
|---|---|---|---|
| H1 | Приложение с `ROLE_DIALER` + `InCallService` может ответить на звонок программно | низкий, документированный API | 1.1 |
| H2 | Абонент слышит TTS, если включить громкую связь и играть TTS через динамик | средний, зависит от OEM | 1.2 |
| H3 | Микрофон в режиме разговора слышит голос абонента из динамика | **высокий**, часть OEM режет | 1.3 |
| H4 | Офлайн-распознавание речи на uk/ru достаточно для диалога по ключевым словам | средний | 1.3 |
| H5 | Полудуплекс (не слушаем, пока говорим) убирает самовозбуждение TTS → микрофон | средний | 1.4 |
| H6 | Задержки терпимы для живого человека на линии | средний | 1.4, 1.5 |

Ключевое ограничение платформы, вокруг которого всё строится: Android не даёт
третьим приложениям доступ к аудиопотоку звонка ни в одну сторону. Бот говорит
через громкоговоритель и слушает через микрофон. Телефон должен лежать на столе.
Подробнее — README, раздел Known limitations.

### 1.2 — Говорить

Статус: 🔄 (код написан и стоит на телефоне 2026-09-24, чек-лист за пользователем)

**Цель.** Проверить H2: абонент слышит бота.

**Делает агент.**

- После `answer()`: `setAudioRoute(CallAudioState.ROUTE_SPEAKER)`, затем `TextToSpeech`
  с приветствием: «Це автовідповідач. Розмова записується. Скажіть, хто ви і що потрібно.»
  (текст и язык — из настроек, по умолчанию uk). Через 8 с после конца фразы — отбой.
- Тумблер в настройках: поток TTS `STREAM_VOICE_CALL` / `STREAM_MUSIC`. Нужен для матрицы.
- Тумблер: маршрут SPEAKER / EARPIECE (проверить гипотезу, что на некоторых устройствах
  динамик наушника ближе к микрофону уплинка — маловероятно, но дёшево).
- В журнал: момент старта и конца TTS, выбранные параметры.

**Проверяет пользователь.** Второй телефон у уха, звонить на тестовый, слушать.

- [ ] VOICE_CALL + SPEAKER: приветствие слышно разборчиво. Результат: … / 10
- [ ] MUSIC + SPEAKER: результат: … / 10
- [ ] Лучший вариант: громкость достаточна на расстоянии 0.5 м от телефона? Результат: …

**DoD.** Есть комбинация с ≥ 9/10 разборчивых приветствий. Она записана в «Результат» и становится умолчанием.

**Результат.**

- 2026-09-24, Mac. Реализовано и поставлено на realme:
  - `voice/Talker`: обёртка над системным `TextToSpeech`. Асинхронный init (запрос до готовности ставится в очередь),
    `setLanguage(uk)` с логом результата и имени голоса, `AudioAttributes` по потоку
    (VOICE_CALL → `USAGE_VOICE_COMMUNICATION`, MUSIC → `USAGE_MEDIA`) плюс `KEY_PARAM_STREAM`, громкость 1.0.
    `onStart` / `onDone` (с длительностью) / `onError` — в журнал.
  - `SytoInCallService`: TTS инициализируется в `onCreate` сервиса (то есть ещё во время звонка телефона, до ответа).
    На `ACTIVE` входящего: лог громкостей VOICE_CALL / MUSIC и режима AudioManager → `setAudioRoute(SPEAKER|EARPIECE)` →
    через 500 мс `speak()` → по `onDone` пауза N с (по умолчанию 8) → `disconnect()`. Все шаги в журнал, на in-call экране
    подпись «greeting…» / «listening window…».
  - Настройки на главном экране, секция «1.2 Speak»: тумблер «Greet after answer», сегменты «TTS stream» VOICE_CALL / MUSIC,
    «Audio route» SPEAKER / EARPIECE, «Hang up after greeting + N s», текст приветствия (по умолчанию из плана, uk),
    кнопка «Play greeting now (no call)» — проговаривает приветствие на MUSIC без звонка.
- **Голос uk есть.** На телефоне один движок — Google TTS (`googletts…20260817`). Проверка кнопкой через adb:
  init 0,65 с, `setLanguage(uk) -> LANG_AVAILABLE`, голос `uk-UA-language`, `onStart` через 0,84 с после `speak()`.
  Никаких загрузок не понадобилось.
- Что не проверено: слышно ли приветствие *в трубке у абонента*. Это и есть H2, чек-лист выше.

### 1.3 — Слышать

Статус: ⬜

**Цель.** Проверить H3 и H4. Самая рискованная подфаза, здесь проект может закончиться.

**Делает агент.**

- После приветствия — 10 с слушания, результат в журнал как текст.
- Два движка за одним интерфейсом `Listener`:
  1. `android.speech.SpeechRecognizer` с `EXTRA_PREFER_OFFLINE = true` (быстро подключить, качество зависит от системного офлайн-пакета языка).
  2. Vosk с маленькой моделью (uk ~ 50 МБ). Модель кладём в APK или качаем один раз с GitHub. Для спайка — кладём в APK отдельным вариантом сборки, чтобы не писать загрузчик.

- Метрика в журнале: время от старта слушания до первого частичного результата.

### 1.4 — Диалог

Статус: ⬜

**Цель.** Проверить H5, H6: полный цикл на живом человеке.

**Делает агент.**

- `DialogMachine`: состояния GREET → LISTEN → CLASSIFY → RESPOND → (LISTEN ещё раз, максимум 2 хода) → BYE → hangup.
- Полудуплекс: `Listener` стартует только после `onDone` TTS, останавливается перед следующим TTS.
- Классификация по словарю ключевых слов в коде, 4 категории: `delivery`, `sales`, `official`, `unknown`.
  Каждой — короткий ответ («Залиште біля дверей», «Не цікавить, до побачення», «Передам, напишіть SMS», «Не зрозумів, повторіть»).
- Расшифровка целиком в журнал: время, категория, что услышали, что сказали.
- Таймауты: тишина 6 с → «Не чую вас, до побачення» → отбой. Общая длина ≤ 60 с.

**Проверяет пользователь.**

- [ ] 10 тестовых звонков со сценариями «доставка», «продажи», «непонятно». Правильная реакция: … / 10
- [ ] Самовозбуждение (бот слышит сам себя и отвечает себе) — не наблюдается. Результат: …
- [ ] Паузы терпимы, человек на линии не кладёт трубку от неловкости. Субъективно: …

**DoD.** ≥ 7/10 правильных реакций, нет самовозбуждения.

- Пакет спайка: `com.ownnet.syto.voice`. Есть (1.0–1.1): `SpikeLog`, `SpikeSettings` (SharedPreferences),
  `ContactsLookup`, `CallRegistry` (текущий `Call` + Compose-состояние для in-call экрана), `SytoInCallService`,
  `InCallActivity`. Будут (1.2–1.4): `Talker` (TTS), `Listener` (интерфейс, две реализации), `DialogMachine`.
  Экраны — в `com.ownnet.syto.ui`: `HomeScreen`, `SpikeLogScreen`, `InCallScreen`.
- Логи — один файл в `filesDir`, ротация по 1 МБ. Формат: `HH:mm:ss.SSS | tag | сообщение`.
- Никакого `INTERNET`. Vosk-модель — в APK (вариант сборки `withModel`) на время спайка.
- Manifest: `InCallService` с `android.telecom.IN_CALL_SERVICE_UI = true`,
  `android.telecom.IN_CALL_SERVICE_RINGING = false`, permission `BIND_INCALL_SERVICE`.
- Работает только пока Syto — звонилка по умолчанию. После тестов пользователь возвращает системную.

## Заметки и находки

- realme UI гасит экран и держит keyguard; `adb shell input keyevent KEYCODE_WAKEUP` его не будит, `KEYCODE_POWER` будит,
  но экран блокировки остаётся. Скриншоты через adb на заблокированном телефоне чёрные. Для визуальной проверки
  пользователь разблокирует телефон сам; агент проверяет по logcat (`adb logcat -s Syto`).
