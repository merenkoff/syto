# Syto — точка входа для любой сессии

Syto (Сито) — Android-приложение: локальное «сито» для звонков и SMS с незнакомых
номеров. Без облака, без `INTERNET` в манифесте. Что и зачем — в `README.md`.

## С чего начать сессию (в этом порядке)

1. `docs/STATUS.md` — где мы сейчас, следующий шаг, блокеры, открытые вопросы.
2. `docs/PLAN.md` — план планов по фазам и гейты между ними.
3. Файл текущей фазы в `docs/phases/` — подфазы, критерии готовности, чек-листы тестов.
4. `docs/DECISIONS.md` — принятые решения. Не пересматриваем без новой записи.

Контекст чата и память сессии не являются точкой истины. Точка истины — файлы `docs/`.

## Как обновлять документы

- В конце каждой сессии и после каждого значимого шага: обновить `STATUS.md`,
  статусы в `PLAN.md` и в файле фазы, новые решения — в `DECISIONS.md`. Закоммитить, запушить.
- Если план меняется — сначала правим md, потом код.
- В файле фазы у каждой подфазы есть блок «Результат». Всё, что узнали на устройстве, пишем туда.
- Новую фазу заводим копией `docs/phases/_TEMPLATE.md`.

Статусы: ⬜ не начато · 🔄 в работе · ✅ готово · ⛔ заблокировано · ❌ отменено / no-go

## Что агент в облачной сессии может и не может

- Может: писать код и документацию, конфигурировать Gradle и CI, собирать проект,
  если в контейнере доступен Android SDK (см. фазу 0).
- Не может: запускать приложение на телефоне, звонить, слушать TTS, проверять микрофон.
  Всё, что требует устройства, оформляется чек-листом в файле фазы. Пользователь выполняет
  чек-лист на телефоне и вписывает результат.
- APK для установки на телефон собирает GitHub Actions и выкладывает артефактом (фаза 0).

## Технические константы

- Kotlin 2.x, Jetpack Compose, minSdk 29 (Android 10), targetSdk — актуальный стабильный.
- Никакого `INTERNET` permission, никакой аналитики, никаких крэш-репортов.
- Пакет приложения: `com.ownnet.syto` (см. D-005 в DECISIONS).
- Язык кода, комментариев, README — английский. Язык `docs/` — русский.
